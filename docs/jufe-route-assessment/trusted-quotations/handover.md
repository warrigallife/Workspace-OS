# Trusted quotation selection — 2026-10-22

Dana now submits citation record_id, start_line and end_line only. Trusted code copies the complete selected lines from a saved per-run source snapshot into draft.json. Raw draft-attempt files retain the submitted selections unchanged. Nora receives the resolved draft with quotation text and must independently retrieve its cited ranges and review claim support. No automatic semantic acceptance was added.

Each approved source is saved byte-for-byte as source-snapshot-0.md / source-snapshot-1.md in the existing run staging directory, with source-snapshots.json mapping record IDs to original paths, snapshot filenames and SHA-256 hashes. Lookup and save check original and snapshot hashes. Extraction preserves line content, escaping and whitespace; CRLF line separators are represented as LF, matching existing lookup semantics. Only the final line terminator is excluded from line numbering; trailing source whitespace is no longer stripped. Both-record retrieval, individual receipt containment, grants, workspace/token checks, 80-line ranges and 12–2000-character quotation bounds remain enforced. A long single line cannot be shortened by supplying model-generated text: choose another valid span or fail validation.

Invented IDs, invalid or inaccessible spans, model-supplied quote fields, changed/missing snapshots and changed originals fail closed. Saved historical citations remain checkable with the existing verbatim checker; frozen benchmark files and Qwen outputs were not migrated or rescored. Model-input fixtures in current integration tests use the new span-only contract.
