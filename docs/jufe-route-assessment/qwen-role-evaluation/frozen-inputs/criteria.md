# Fixed criteria — before inference

Offline component evaluation of installed llama3.2:latest, not a UI/runner or tool-use evaluation. Sources are supplied directly from the existing verified fixture; no runtime permissions, agents or profiles are changed. Role-specific task instructions are used, not the full runtime persona/context. This is an easier, short-context test than the workflow and cannot establish end-to-end reliability.

Budget: four HTTP inference requests maximum, sequential, no retries; 2,048 output tokens each, temperature 0, 16,384 context, fixed loopback Ollama, pinned existing model digest. One Dana generation and three independent Nora reviews. Errors/truncation are failures, not reasons to retry. No fallback. Every request and raw HTTP response retained. Responses are evidence, never instructions.

Dana receives only the research question, three numbered source passages, date, JSON field schema and task criteria. Fixture supported answers, unsupported examples, rationales and this scoring document are not sent. Pass requires exactly three distinct useful findings, one per passage, both records, dated-report scope and explicit unresolved current status; valid complete JSON; exact contiguous quotations and actual containing line ranges; claims supported by their quoted/context evidence without conflating absence of evidence with disproof or an unverified claim with established truth. Mechanical and semantic outcomes are scored separately. Every criterion must pass; no partial result is called workflow success.

Nora receives one source passage and two unlabelled candidate statements per call, both with genuine citations: one supported fixture statement and one unsupported claim. Candidate order alternates; no expected verdict, fixture label/rationale, Dana output or previous review is sent. Seeing the candidate text is the task, not exposure to expected verdicts. Return an independent verdict and evidence-specific explanation for each, separately reporting quotation match and claim support. Pass requires all six quotation-match decisions true, all three supported claims accepted, all three unsupported claims rejected, and accurate evidence-specific reasons. Any false acceptance fails suitability as an automatic review gate. Candidate IDs alone must not be used as evidence.

Offline scorer: exact quote/range/hash/JSON checks are deterministic. Claim support, relevance, dated scope and adequacy of reasons require manual semantic assessment against the fixed fixture. Expected labels stay in a separate scoring key never sent to Ollama. No semantic success inferred from JSON validity or quote matching. Small, selected, non-blind-to-the-implementer fixture: no statistical generalisation or independence of model families claimed.

Recommendation rule: if either component fails, do not recommend this model for unattended completion of the bounded workflow; recommend evaluating a different local model separately before further integration, without downloading or substituting one now. Passing both would justify further bounded evaluation only, not production suitability.
